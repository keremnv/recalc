# Persistent read state and cache policy

Persistent artifacts live under the configured user cache in `read-engine/`; run receipts live under `runs/`. The default root is `$XDG_CACHE_HOME/librecalc-agent`, or `~/.cache/librecalc-agent`. The launcher requires a user-owned cache and makes its root and run directory private (`0700`). A symlinked root or run directory is rejected. Each artifact key hashes the workbook's whole-file SHA-256 with package runtime, decoder, narrow semantic-contract and format versions. The workbook remains authoritative.

The initial format is `JSONZ_MEMORY_V1`: deterministic typed JSON compressed with zlib in a magic/version/source-bound envelope. It uses no executable deserialization. The sidecar carries the package runtime version; artifact discovery requires it to match and requires a key derived from that version. The semantic envelope carries decoder, contract, format and source identity. Warm discovery verifies sidecar, envelope and whole artifact; the serving process fully validates payload hash, schema and typed values before serving. A second source hash at first direct load protects the bootstrap-to-script interval. Build publication uses a key-specific advisory lock, temporary file, fsync and atomic rename. A racing reader accepts only a complete verified generation.

Bounds include 256 MiB compressed and 512 MiB uncompressed artifact payloads, 512 sheets, ten million cells, a two million character scalar, 10,000 XLSX ZIP members, 512 MiB declared ZIP expansion and 256 MiB XML parts. Direct-path rejection falls back to reference openpyxl. Corrupt, missing, stale or incompatible artifacts rebuild; build failure leaves reference execution available. The user may delete derived artifacts while no invocation uses them. Automatic eviction is deferred: the initial product has a per-artifact bound but no global cache quota, so disk growth is a known operational risk to address before release scale-out. Old-format artifacts are never served under a new key.
