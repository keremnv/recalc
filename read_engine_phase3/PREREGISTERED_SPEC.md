## Safe artifact: JSONZ_MEMORY_V1

- One format only: a deterministic binary envelope with 8-byte ASCII magic `LCRE3JZ1`, 4-byte big-endian UTF-8 header length (maximum 16 KiB), canonical JSON header, 8-byte big-endian compressed payload length (maximum 256 MiB), zlib level-1 compressed canonical UTF-8 JSON payload (uncompressed maximum 512 MiB), and 32-byte SHA-256 checksum of all preceding bytes. Reject extra/truncated bytes. No pickle, `eval`, or code execution during load.
- Header binds exact source whole-file SHA-256, decoder SHA above, semantic contract `PHASE1_NARROW_V5`, format `JSONZ_MEMORY_V1`, sheet count and payload SHA-256. Artifact key is SHA-256 of `source_sha|decoder_sha|contract|format`. Path `<persistent-cache>/read-engine/<key>.r3jz`, outside UUID run directories. A separate canonical JSON sidecar is published last and records artifact SHA/length and identical identities. Manifest and envelope must agree. Write temp file, flush/fsync, atomic rename, sync directory; publish manifest last in the same manner.
- Payload encodes ordered sheet names/bounds/merged ranges and sorted coordinate records `[coordinate,data_type,typed_value]`. Typed values use the frozen Phase-1 `_value_to_json`/`_value_from_json` vocabulary for scalar, datetime/date/time/timedelta, ArrayFormula and DataTableFormula. Strictly validate JSON shape, allowed value kind/data type, sheet/cell counts, coordinate form, integer bounds, string lengths and relationships before constructing a `MemoryBook`. Maximum 512 sheets and 10 million total cells; sheet names <=255 Unicode characters, coordinates <=12 ASCII characters, individual strings <=2 MiB. Reject anything outside limits and select reference/rebuild according to the parent lifecycle. These limits cover the frozen population and are not tuned after timing.
- Each invocation hashes every discovered top-level `*.xlsx` source file before artifact lookup, matching RC eager discovery scope. Valid artifacts are fully validated and loaded from a fresh process when the script calls `openpyxl.load_workbook`; parent only discovers/verifies/publishes state. A missing/stale/corrupt artifact is rebuilt from direct OOXML before child launch, with `BUILT`; a valid artifact is `REUSED`. If direct construction or validation fails, fail closed to normal reference openpyxl with an explicit event. No stale bytes may be served.
- Pre-timing gates: artifact round-trip parity with frozen `MemoryBook` across all 39 Phase-1 construction workbooks (including the oracle-unavailable book, compared to decoder state); fresh-process reopen on all 51 Phase-1 traces where practical; missing/truncated/source-mutated/version-mismatched rejection on fixed representative staged copies. These do not generate performance claims or alter populations. If the safe format cannot reproduce the state, stop.

Correctness outweighs serving: any uncertain operation falls back, and mismatching treatment is never scored as exact. ## Control, states, timing, order

- Stage source workbook/script **outside** each command timer, as old RC did. Reuse the same staged path within a scored session but restore source workbook/script bytes before each invocation, outside the timer. Verify hashes. Distinct workloads/repetitions have private staging and persistent cache roots.
- For each primary workload: one unscored CONTROL and one unscored treatment cold run on a separate discarded cache, then **three scored repetitions**. Each repetition starts with an empty private persistent cache and executes five actual CONTROL and five actual treatment commands on reset staged task state. Treatment invocation 1 is `T-COLD` (`BUILT` if admitted/contact-capable); invocations 2–5 are `T-WARM` and require `REUSED` for every contacted artifact. Reference-only scripts may have no artifact and are labeled `NO_ARTIFACT`, not falsely warm. Pair CONTROL/TREATMENT at the same invocation index. Interleave order by deterministic seed 20261011 and AB/BA parity of shuffled workload position, repetition and invocation index; treatment order remains cold then warm. No outcome-dependent rerun.
- For each secondary workload: one unscored CONTROL and treatment cold warm-up on separate cache, then **two scored repetitions** of one CONTROL, one T-COLD and one T-WARM using private cache per repetition. Use the same parity/seed rule. This view measures prevalence/cold/warm only, not session N>2 inference.
- T-COLD and T-WARM: external `perf_counter_ns` immediately before command subprocess invocation to exit, including entire parent and child lifecycle; no staging. WARM is valid only with `REUSED` witness for a contacted workbook. SESSION N=1,2,3,5 is the **sum of the N observed full command walls** in that repetition, compared with the sum of N observed independent CONTROL command walls. Restaging/parent benchmark bookkeeping is excluded symmetrically. This is observed cumulative command time, not extrapolation.
- Scored workload statistic is the median of three primary repetitions per arm/regime, paired to the identical workload; N session ratios use median per-workload session treatment/control totals. Secondary uses median of two repetitions. No N=10.
- Timeout 180 seconds per command as old RC. Capture stdout/stderr exact bytes; retain normalized-address comparison separately. OS cache uncontrolled, no cold-disk claim. Old RC had one warm-up per arm, three scored reps and fresh cache per invocation; Phase 3 differs deliberately by persistent cache across treatment invocations and by five-command sessions. These differences are reported.

## Semantic gate, stop rules, analysis

- Before scored timing, run one unscored primary correctness pass of CONTROL, T-COLD and T-WARM for all 22 identities. Compare exit code, timeout, exact stdout/stderr, normalized stdout/stderr after replacing only volatile `ArrayFormula`/`DataTableFormula` object addresses (same old RC diagnostic method), all workbook package hashes/parts and other output-file bytes. Classify `EXACT`, `VOLATILE_ONLY_DIFFERENCE`, `GENUINE_SEMANTIC_DIFFERENCE`, or `EXECUTION_FAILURE`. Record the three primary old failures and the representative-only fourth separately. Control output must be self-consistent across repetitions; do not call a volatile control result a treatment semantic defect without evidence.
- If any primary old or new genuine semantic mismatch remains, **stop before scored speed or secondary prevalence**, report exact workload/cause and mark aggregate speed `NOT SUPPORTED`. A diagnostic wall time may be retained, but no favorable speed claim. Likewise stop for broken safe state parity, unverifiable population identity, stale/corrupt reuse, missing warm witness on a contacted script, or unreliable clocks. Do not widen read contract/eligibility or add formats to rescue a result.
- Where the gate passes, score all 22 primary workloads without exclusion. Then run exact 30 secondary view with its own semantic classification; secondary mismatches invalidate secondary speed claims, not the already-scored primary endpoint. Preserve all raw rows/events.
- Per endpoint report paired workload median ratio, geometric mean, min/max, faster/slower/tied, 2,000-resample percentile bootstrap interval (seed 20261011), and task-cluster sensitivity over distinct task IDs. Do not interpret 22 script rows or 30 representative rows as independent task-population draws. Historical bridge table includes every primary workload's old ratio, new cold/warm, old/new semantic status, artifact witness and reference fallback.
- Decision labels: `READ ENGINE SEMANTICS` supported only if all 22 primary workload comparisons are exact or volatile-only; `COLD PRODUCT-SHAPED SPEED` supported only if semantically valid and primary median cold ratio <1 with >11/22 faster and bootstrap median upper <1; `WARM PRODUCT-SHAPED SPEED` same plus 22 valid reuse witnesses where contact occurs; `INTEGRATION CANDIDATE` earned if semantics hold and at least one cold/warm/N=2,3,5 full-boundary regime meets that favorable rule. The labels are Phase-3 offline decisions, never public claims.
