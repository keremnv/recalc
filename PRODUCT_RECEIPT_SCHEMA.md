# Invocation receipt schema

`status --json` reads the latest run from the private cache. Its compact summary contains `invocation_id`, `route` (`REFERENCE_FAST_PATH`, `DIRECT_RUNTIME`, or `DIRECT_WITH_FALLBACK`), `admitted` (bool) plus `admission_reason` (`admitted`, `not-admitted`, `runtime-disabled`, or `setup-failed`), artifact status (`BUILT`, `REUSED`, `NOT_APPLICABLE`, or an unavailable/unconfirmed state), direct-served load count, fallback reasons, `target_status` (exit code and signal), `assurance_status` (`PASS`, `FAILED`, or `NOT_REQUESTED`), effect capture/validation status, capture record count, failure code and run-directory path. (The rc1-era `read_gate` classifier string was retired in rc2; raw classifier detail remains in the run-dir `setup.json` under `admission_decision`, which is unstable support material.)

The run directory keeps a native observer receipt and small setup/runtime/capture state files. It does not ship benchmark JSONL rows or per-cell traces. A successful `REUSED` status requires a verified artifact and actual direct-serving contact; setup-only candidates are marked unconfirmed. A missing final observer receipt is an assurance failure. Research profiling is separate from this product receipt.
