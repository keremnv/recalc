## Contract, artifact and treatment scope

- Freeze Phase-1 narrow contract, direct decoder, `JSONZ_MEMORY_V1` format and binary bytes/schema, source whole-file SHA-256, artifact key, sidecar, atomic publication, child full decode, child source recheck, openpyxl fallback, whole-script classifier, process-local bootstrap, parent/child process count, capture, diagnostics policy and ordinary script interface. H0 uses frozen Phase-3 code. H1 changes only **warm parent artifact ownership and lazy parent builder import**.
- H1 warm valid candidate parent performs source SHA, key/path/sidecar existence and identity, artifact existence/declared size/limits, magic, header identity/version/length, compressed length, whole-artifact checksum and sidecar artifact SHA. It does **not** decompress payload, check semantic payload SHA, parse semantic JSON, schema-walk cells, convert typed values, or construct `MemoryBook`. The child retains the complete Phase-3 `safe_artifact.load()` validation and constructs the sole serving `MemoryBook`. Parent must not import Phase-1 `prototype`, `lxml`, or openpyxl merely for warm validation. An invalid/missing parent candidate enters the **unchanged cold build** through a lazy import of frozen Phase-3 `safe_artifact.ensure` (which itself validates/builds/publishes). Parent does not weaken integrity: malformed header/identity/whole-artifact hash is rejected before launch; semantically corrupt but integrity-consistent payload is rejected by the child before serving and falls back to reference.
- A warm parent may internally mark `REUSE_CANDIDATE`, but the persisted summary and benchmark may call it successful `REUSED` only if matching child `direct_served_load` follows full child decode with no `artifact_runtime_failure`. If not, final status is `REUSE_REJECTED` or `REUSE_NOT_CONFIRMED` with reason and no warm-speed credit. This status finalization is part of the trust-boundary change, not a fallback-policy change. H0's frozen status behavior is not modified.
- H1 cold missing/stale/invalid path uses the same frozen direct decoder/serializer/publisher and child load; only import timing/module ownership may differ. No other optimization, proxy change, merged-cell or iteration change, new format, source-hash change, or capture change is allowed.

- `PY`: `<venv-python> <workdir>/workload.py`; `H0`: `<venv-python> read_engine_phase3/harness.py run --workdir <workdir> --cache-root <cache> --run-root <runs> <workdir>/workload.py`; `H1`: same command with `read_engine_phase4/harness.py`. H0/H1 child use frozen Phase-3 sitecustomize/runtime and ordinary openpyxl interface. Capture remains on.
- One unscored warmup per workload and arm on discarded private caches. Then one unscored semantic gate per primary workload: direct Python, H0 cold/warm and H1 cold/warm on independent private caches, exact output/state comparison and reuse confirmation. Run corruption/invalidation gates before scored benchmark. If any gate fails, stop; any wall rows are diagnostic only.
- Three scored repetitions per workload. Each repetition begins with absent H0/H1 artifacts and executes five real invocations of each arm (one cold, four reused warm) on reset task state. Workload order is fixed Phase-3 primary ID order shuffled once with seed `20261104`. No outcome-dependent rerun or exclusion. Timeout 180 s per command. A score failure stops subsequent scoring; partial rows retained and aggregate marked invalid.

## Correctness and invalidation gate

- Use Phase-3 equality rules: exit code/timeout parity; exact stdout/stderr bytes, with only Phase-3 volatile formula-object address normalization separately; post-run files and XLSX ZIP-part hashes. Classify `EXACT`, `VOLATILE_ONLY_DIFFERENCE`, `GENUINE_SEMANTIC_DIFFERENCE`, `EXECUTION_FAILURE`. All primary gate/scored pairs must be exact (the Phase-3 primary was exact). Compare PY vs H0, PY vs H1, and H0 vs H1. Require direct-serving contact and reference fallback count/reason parity H0/H1 per invocation. No new genuine difference. A child semantic failure invalidates warm reuse even if parent integrity checks passed.
- On fixed preregistered source generations, probe H1: no artifact → `BUILT`; valid artifact → child-confirmed `REUSED`; truncated artifact; modified artifact byte; format-version mismatch; decoder-version mismatch; contract-version mismatch; same staged path with changed source bytes → no H1 state served; restored source bytes → original valid state reusable; and a syntactically integrity-consistent but semantically invalid payload → parent candidate may pass, child must reject before serving and use normal reference route, never report successful `REUSED`. Probe source identities are the first and second unique source workbook hashes in Phase-3 primary ID order, fixed before results. These are lifecycle/correctness probes, not scored timings. Preserve the source byte hashes in records.
- If any invalidation or semantic gate fails, stop before aggregate speed conclusions. Do not fix an unrelated defect in H1; document and use a versioned amendment if protocol itself is defective.
