# Design review and chronology

This review indexes an **already completed** claim-discovery study. It is retrospective and does not amend the hashed 2026-09-22 preregistration or its gates. The subsequent independent affordance study is also complete and has a frozen stop decision. No new provider run was authorized by this index.

## Historical rationale and sample size

The original study selected five tasks per family from prior H0/control traces, emphasizing submission history and large visible-inspection headroom. The selection manifest records the ranks and excludes treatment advantages and score deltas. The 30-task validation reservation was sampled separately with seed `20261001`; neither claim-discovery nor later affordance treatment ran on it. Two reserved tasks, `Financial_Model:10_01` and `Template:07_02`, had earlier, different-architecture H1 runs **before** reservation. This limits how untouched the reserve is for a future claim, even though the later studies did not open it.

An earlier paired checkpoint gave log input-ratio SD 1.027 across 29 pairs, with family SDs Template 1.047, Financial_Model 0.532, Debugging 0.973. This is a design-scale estimate from a different intervention, not a treatment effect estimate for salience. At that SD, normal-approximation two-sided 80% power would require roughly 746 paired tasks for a 10% reduction, 166 for 20%, and 65 for 30%. Fifteen tasks could only give directional mechanism discovery; five per family cannot establish family-general savings or capability equivalence. The budget cap of $25 and expected cost constrained the original choice. The actual provider charges were far below the runner's uncached-blind estimated spend, so the pre-run cost model was conservative.

## Factorial identification

The 2×2 was a reasonable compact *profile* comparison: C/A and D/B vary the inspection note, B/A and D/C vary helper exposure, and D/A tests the full candidate surface. All arms used ordinary openpyxl, with Candidate A, substrate and capture off. The provider-facing bash/view/submit schemas were identical. Exact S notes were 38 local `cl100k_base` tokens each, same placement; first-request provider input C−A was near zero. H-on added an 83-token local-estimate helper note, and first-request B−A and D−C differences were about 83 provider tokens. Because that note is resent in each request history, overhead must be counted in total provider input. It was counted.

The factorial does **not** isolate helper execution from helper description or importability. H toggled a truthful helper addendum and Python module availability together. The neutral S note also directs the agent to check and submit, while the salience note directs inspection; their token counts match but behavioral content is not perfectly parallel. The S cue contains no scorer, token, or task-specific answer advice. Provider routing policy was common, yet actually served providers changed across calls and arms. Four concurrent arm workers reduced elapsed time but did not pin provider/cache order. The request decomposition uses exact bytes and a rough local token proxy for categories; provider-reported total input remains the endpoint.

A cleaner *hypothetical pre-run* test of the leading inspection hypothesis would have concentrated the same spend on a two-arm, provider-pinned salience contrast with matched note functions and more tasks. That is not the frozen experiment and cannot replace its result. The later fresh affordance test separately probed helper-cue explanations; it found zero factual helper calls and no robust shippable effect. Its preregistered stop rule closes another token-mechanism search under that profile. Any renewed study would require a materially independent rationale and new identity, not a retrofit to these data.

## Preserved alternatives

The original hypothesis predicted fewer fat observations, smaller accumulated history, and lower input per call. Alternatives were fewer calls from shorter edit/check trajectories, more calls that erase per-call savings, early termination, completion/score differences, provider censoring, caching/routing, helper-note priming without adoption, and a few pathological tasks. The first study's observed broad-view reduction did not yield lower observation bytes or input per call; D/A lower total input came principally from fewer calls. Two Template trajectories dominate its apparent full-surface reduction. These are findings under the frozen design, not revisions to the preregistered hypothesis.
