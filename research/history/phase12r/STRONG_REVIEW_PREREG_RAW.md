Reviewer role: independent design/diagnosis only. This reviewer did not generate, recalculate, repair, or score a workbook. Model identity available in this session: Codex based on GPT-6; a more specific backend identity or a verified strength ranking is not exposed, so neither is claimed.

Reviewed: `phase12r/PREREGISTERED_REPLAY_SPEC.md`, `PHASE12_POST_EDIT_VERIFICATION_AB_REPORT.md`, and the current official evaluator at `benchmark-data/SpreadsheetBench-2/evaluation/evaluation.py`. No outcome predictions are made. Phase-12 **D — DEMOTE**, the cache mechanism finding, and the nuisance finding carry forward unchanged.

## Overall assessment

The proposed copied V0/V1 experiment is appropriate for the effect of the specified LibreOffice pipeline on the specified scorer. A cache transplant witness is a useful attribution control. Neither unchanged formula text nor equal aggregate witness scores alone establishes that LibreOffice evaluated unchanged workbook semantics. Freeze a more operational rule for semantic changes, provenance, and witness agreement before calling any recovery cache-only.

## Alternative explanations for falsely labeling recovery cache-only

1. **Same formulas, different inputs or calculation semantics.** LibreOffice can change literals, defined names, table definitions, date epoch, precision/iteration settings, array/spill structure, or external-link state before producing caches. Copying those caches back into V0 can reproduce V1 scores even though the caches were calculated under changed semantics. The witness establishes cache sufficiency for the score, not automatically the source of those caches. Require an explicit semantic fingerprint and classify an unexplained difference as ambiguous. At minimum compare sheet identity/order, formula coordinates/text/array ranges, typed nonformula values (resolved strings, not shared-string indexes), defined names, merged ranges, table definitions/references, workbook date system, and calculation settings that affect results. Ordinary automatic/full-calculation flags can be allowed; iteration and precision changes cannot simply be treated as volatile metadata. Styles can affect parsed dates and color-scored outcomes, so a blanket styles exception is unsafe.
2. **Error cache changes evaluator branch.** The inspected scorer compares formulas whenever either compared cached cell contains an Excel error; it also equates certain error/display placeholders and empty/zero values. Recalculation can improve an official score by selecting this fallback, without supplying a correct numeric result. This is still a cache-mediated score effect if properly proven, but it is not evidence that all newly materialized values are numerically correct. Report error-cache recoveries and formula-fallback behavior explicitly using the existing scorer outputs and cache census; do not describe them as semantic correctness established by recalculation.
3. **Equal aggregate scores conceal different cells.** V1 and witness can have equal modification/regression ratios while getting different cells right. Require identical scorer-observed cell-match vectors, or a demonstrably sufficient equality of the scorer's observed typed values/formulas/colors at every assessed cell. Equality of the three aggregate outcomes is necessary but insufficient for the strongest attribution class.
4. **Cache representation is part of the witness.** A string/error/numeric cache requires the correct cell type as well as the `<v>` content. Transplant resolved cached strings into valid formula-string representation; do not transplant shared-string indexes that refer to V1's different string table. Preserve formula text/attributes and all noncache XML. Validate with tests for numeric, empty/string, Boolean and error caches, and array/shared formula cases. Treat unsupported array spill representations conservatively.

## Confounds that invalidate or weaken V0 → V1 comparisons

- **Unverified historical submission bytes.** A run-local candidate need not be the artifact actually scored. An aggregate historical-score match does not prove identity. Keep unverified candidates in a separately labeled normalized replay cohort; exclude them from the primary prevalence of *historical submissions* and from historical-failure corrections. Do not let the P1 description's fallback silently enlarge its primary denominator. Exact archived identity or unambiguous recorded provenance is required.
- **Evaluator/data drift.** Hash the evaluator, benchmark row/answer-position and category/mode flags, input, golden, and relevant dependency versions. Paired current V0/V1 remains valid even when historical evaluator identity is unavailable. Separate byte-verified, historical-score-reproduced corrections from current-environment effects. Historical numerical reproduction alone cannot certify historical evaluator identity. Preserve the scorer's exact zero-denominator and rounding behavior; do not substitute an intuitive definition of exact correctness.
- **Asymmetric scoring setup.** V0, V1 and witness need the same task metadata, input, golden, library versions, staging names and score-call arguments. Do not recalculate gold/input within this experiment. Existing reference caches are part of the frozen official scoring target; recovery against that target does not independently validate reference semantics.
- **Undetected nondeterminism.** Freeze unsupported detection before results, including volatile function matching outside string literals and function namespaces, and enumerate unknown/UDF/external-data/iteration cases. Merely scanning the short volatile list is not a complete guarantee. A fresh profile and fixed locale do not make volatile workbooks deterministic. Explicitly retain unsupported cases and their reasons.
- **Differential artifact survival.** This is a census of retained eligible outputs, not all historical attempts or arbitrary future agents. Report inventory counts, missing-output counts and task/category retention; do not extend corpus prevalence to no-submit runs.

## Rule most vulnerable to hindsight

“No unrelated semantic workbook change plausibly explains the gain” is presently the main discretionary rule. Replace it with a frozen allowlist of representational changes, required equality checks, and an explicit ambiguous fallback. Never decide that a formula rewrite is harmless because its score improves. Function-case normalization must tokenize function identifiers outside quoted text, not uppercase whole formulas or names. Preserve a separate raw formula-text/attribute equality flag: expansion of shared formulas proves an allowed equivalence, not literal equality of the original encoded formula elements.

The broad/narrow baseline rule also needs a fixed inference population: “eligible ordinary tasks” could later mean P1, P1+P2, or whichever cohort supports a decision. Use P1 for primary baseline prevalence; report P2 validation by phase/arm and discovery overlap separately. If P1 coverage is insufficient, say so rather than silently switching denominators. Define whether >=10% in two families means >=10% overall plus any recovery in two families, or >=10% separately within each of two families. Require minimum distinct affected tasks in each implicated family for the broad rule as well as the narrow rule. State how mixed gain/harm cases count.

## Simpler discriminating replay

The existing V0 → V1 plus a cache-only sufficiency witness is the right bounded design; additional trajectories or verifier diagnostics are unnecessary. Make the witness stronger rather than adding an exploratory arm:

1. Freeze exact provenance and input/semantic fingerprints.
2. Recalculate the copied candidate once under the fixed policy.
3. If formulas and required semantics pass the frozen equality rules, transplant only typed formula-cache payloads into V0.
4. Require identical scorer-observed outcomes at the cell level and the same official aggregate scores as V1.

Use a no-op witness (V0 caches transplanted into V0) in plumbing tests to demonstrate that XML serialization/transplant code does not itself change scorer observations. This is a deterministic implementation test, not an additional causal treatment. If the semantic fingerprint fails, the sufficiency witness may still be recorded but cannot elevate the pair to cache-only.

## Failure/exclusion and threshold corrections

- Keep RECALC_FAILED, RECALC_UNSUPPORTED, evaluator errors and genuinely unchanged results distinct. Unsupported is not “no material effect.” Report lower-bound recovery prevalence over all eligible cases plus conditional prevalence over successfully comparable cases and a simple unresolved-case upper bound. This prevents high failure rates from being mistaken for stable historical evidence.
- Classify evaluator read failures using explicit status or validation; the official scorer sometimes converts exceptions into ordinary-looking zeros. A zero score with an error string is not necessarily an ordinary semantic failure. Record zero assessed cells explicitly.
- Freeze exact reproduction tolerance, score materiality, and all Gate-B denominators. For example, use >=0.01 absolute returned-score change for materiality, but report all raw counts and continuous deltas. Gate B should say whether it is evaluated only after full replay or at specific checkpoints and what denominator includes unsupported cases. Freeze ledgers before review; no hindsight reclassification.
- A positive baseline-correction finding supports recalc-before-score under the tested deterministic envelope. It does not by itself identify incremental benefit from also recalculating before submission, once evaluation already recalculates. Recommend submit hygiene separately as an agent-environment policy, with that causal limitation explicit. Neither recommendation authorizes production changes during this phase.
- Zero-model replay accounting should say zero trajectory/API calls and zero replay model cost; reviewer use is permitted but should be recorded separately, rather than claiming the whole phase involved no model use.

## Priority before freeze

Required: isolate byte-unverified candidates from historical primary prevalence; operationalize semantic identity and witness equality; fix baseline and surprise denominators; handle scorer error fallback and hidden evaluator errors explicitly. Recommended: no-op witness tests; uncertainty bounds for unresolved cases; clear distinction between scorer fairness evidence and submission-tooling policy. These corrections change the reliability of attribution, not the desired outcome or numerical thresholds after observing results.
