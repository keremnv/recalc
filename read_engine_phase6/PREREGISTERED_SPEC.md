## Selected H2 and immutable semantics

- Arms: PY = direct `<venv> workload.py`; H0 = frozen Phase-4 parent→child; H1 = frozen Phase-5 one-interpreter; H2 = selected native observer→**real** `<venv> workload.py` fresh script interpreter. H1 is a performance reference, not semantically acceptable. No treatment-specific imports/source changes/AST rewriting.
- H2 observer owns bounded CLI validation, run directory/context, **external exact-byte pre/post `.xlsx` observation**, `fork/execve` child/wait, raw exit/signal state, optional changed-file helper, and compact final receipt. It does not import Python/openpyxl or touch artifacts. Child `sitecustomize` owns unchanged config/classifier, top-level XLSX discovery, source SHA, frozen Phase-4 integrity/build, frozen full safe artifact semantic load through unchanged Runtime, proxy/reference fallback and runtime telemetry.
- Observer snapshots recursively like frozen capture: path suffix `.xlsx`, omit a file whose basename contains `.tmp`, retain pre bytes; post-snapshot compares exact bytes and file set. For no changes it emits an empty effect record. For any created/deleted/changed XLSX, it stages the captured pre bytes and invokes the frozen `capture_wrap_timed` via a separate post-termination Python helper **inside the external timer**, even after child `os._exit`/fatal signal. The helper preserves frozen delta/validation/replay semantics. No heuristic metadata-only equality. Snapshot/capture errors fail the assurance gate.
- H2 child bootstrap may write a prepared artifact-status record before user source. Final successful `REUSED` requires both prepared status and `direct_served_load` after full safe artifact decode. Abrupt termination can leave serving witness `UNKNOWN`, never a false reuse. Full whole-file source SHA, artifact identity/version, integrity, frozen Runtime source recheck, atomic publication, and fallback remain unchanged. No full semantic artifact decode in observer.
- Observer inherits stdout/stderr directly to script child and leaves additional non-CLOEXEC descriptors inherited. Child gets real script argv/cwd and guarded sitecustomize via `PYTHONPATH`; frozen Runtime is installed before source execution. `waitpid` distinguishes normal exit and signal. Observer persists receipt after post-capture, then exits with the exact normal code or restores default signal disposition and re-raises the same signal on itself. Signal forwarding from an external process group must not accidentally kill observer before capture; child signal disposition is reset before exec.
- No merged-cell, workbook iteration, decoder, artifact format, classifier, proxy, source freshness, reference fallback or public config changes. No artifact semantic construction in observer. H2 may pay child-side construction before script on cold invocations; that is part of H2 and fully timed.

- Build an unscored fixture suite for all: module `__name__`, `__file__`, `__package__`, `__spec__`, `__loader__`, `import __main__` in body and atexit; argv, `sys.path[0]`, cwd, environment and extra inherited FD; local/repeated import/module cache; stdout/stderr/flush; return, `SystemExit(0)`, nonzero SystemExit, uncaught exception; `try/finally`, file flush, atexit output and workbook save; subprocess; caught SIGUSR1, SIGINT/KeyboardInterrupt, SIGTERM/fatal child signal; `os._exit`. Fatal signal is self-directed only inside a dedicated subprocess fixture; no unsafe system test. H2 vs PY classification: `EXACT`, `OBSERVABLE_DIFFERENCE_BUT_ACCEPTABLE`, `PRODUCT_CONTRACT_VIOLATION`, `UNTESTABLE`.
- H2 must repair H1's atexit-`__main__` and abrupt post-observation failures. It must take an exact post snapshot and persist a receipt after `os._exit` and fatal termination, preserving exit/signal status as directly as platform permits. A missing receipt/effect, false status, lost inherited stdout/stderr or FD, or script module-identity/traceback violation stops scoring. H0/H1 comparison is retained in fixture ledger as context.
- Before scored timing, fixed-source lifecycle probes cover cold `BUILT`, valid `REUSED`, missing/truncated/modified/format/decoder/contract-mismatched artifacts, integrity-consistent schema-invalid payload, same path with different source bytes and restoration. ## Scored protocol and analysis

- One unscored warmup per arm/workload on discarded caches, after gates. Three scored repetitions per workload; each repetition uses independent H0/H1/H2 cache roots initially absent and five actual commands/arm, first cold then four warm with reset task state each invocation. PY runs independently each invocation. Workload order is the original primary IDs shuffled with seed `20261106`; arm order cyclically rotates `[PY,H0,H1,H2]` by `(position+rep+invocation)%4`. Three-arm frozen code is not modified. 180-second timeout per command; any scored correctness/reuse failure stops further scoring and leaves partial raw rows invalid for aggregate claims.
- External timer starts immediately before launching each complete arm command and ends at command exit, excluding symmetric staging/benchmark comparison. H2 clock includes native observer startup, exact pre snapshot, target interpreter/bootstrap/build/reads/fallback, wait, exact post snapshot, changed-file helper if used, receipt and shutdown. COLD invocation 1: absent artifact. WARM invocations 2–5: semantic `REUSED` required. SESSION N=1,2,3,5: observed sums of complete commands from cold start. All four arms use the same RC Python, staged workdir bytes and normalized environment. No extrapolation.
- Per workload: median cold over repetitions; median warm positions 2–5 within repetition then median over three repetitions; session median over repetitions. Paired ratios H2/H0, H2/H1, H2/PY, plus H0/H1/PY context. Report median, geometric mean, range, faster/slower/tied, 2,000 bootstrap percentile interval (seed `20261106`), and task-cluster caveat (22 scripts/14 tasks). Three short Templates and four unchanged fallback scripts receive per-workload tables. Raw rows retain all arm-order/time/witness/profile fields.
- Capture/process semantics and full-boundary speed are **independent**. `PROCESS_ASSURANCE=SUPPORTED` only if H2 repairs H1 process/assurance violations at the fixture/fixed gates. `FULL_BOUNDARY_SPEED=SUPPORTED` only if H2/PY warm median <1, >11/22 scripts faster, and script-bootstrap upper bound <1, with exact semantic/reuse gates. Report H2/H0 causal process-architecture effect separately. H1's archived/Phase-6 timing is a ceiling/reference; it cannot earn integration.
- Architecture outcome exactly A (H2 fast+assurance supported, `THIN_OBSERVER_ARCHITECTURE_CANDIDATE=EARNED`), B (fast+assurance not supported), C (not fast+assurance supported), or D (neither). Cold/session and H2/H1 proximity do not override the independent gates. No public claim or product integration follows automatically.
